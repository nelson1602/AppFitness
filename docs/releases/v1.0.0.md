## What this product is

An **offline-first, bilingual (Spanish / English) fitness, nutrition, progress
and general-wellness app** with deterministic, explainable iCoach guidance. It
runs on device against a local SQLite database and synchronises to the backend
when it can; every feature works offline first.

**It is not a medical product.** ADR-P017 rebaselined public v1 around wellness
and made the retained medical domain **dormant** — see *The medical domain*
below.

## Highlights (user-facing)

- **Deterministic iCoach guidance** — calorie and macro targets, training
  recommendations and a weekly workout plan, computed on device from the user's
  own data. Identical inputs always produce identical outputs; no network and no
  randomness in the generator.
- **Full Spanish and English**, at parity — 1063 key pairs, with dates, numbers
  and units rendered through a shared locale-aware formatter.
- **Nutrition** — food catalogue, 15-day meal plan, food logging with daily
  totals, and dietary preferences and allergies surfaced as non-blocking
  warnings.
- **Workout** — routine builder, workout logging (sets, repetitions, weight),
  exercise library including user-created custom exercises, and a read-only
  iCoach training plan.
- **Progress** — body weight and measurements, deterministic weekly snapshots
  (average weight, training volume, calories, workout count, deload flag),
  in-house trend charts and a dashboard progress card.
- **Sync conflict review and resolution** (ADR-P030) — when two clients disagree
  about the same record, the app shows both sides in plain language and lets the
  user decide; choices made offline are stored and settle on reconnect.
- **Account recovery and email verification** (ADR-P026) — password reset and
  verification, with the verification reminder advisory rather than blocking.
- **Advisory onboarding** (ADR-P027) — a three-step first-run checklist that
  gates nothing; every other surface stays usable.
- **Account deletion** (`/delete-account`) — immediate and irreversible
  (ADR-P011).

## The medical domain

ADR-P017 Decision 4 removed the medical domain from public v1. The code, schema
and tests are **retained and still compile**, but `MedicalModule` is excluded
from the API composition root, so:

- no medical HTTP route is reachable (`POST /medical/evaluations` returns 404 by
  design), and
- the medical sync handlers are never registered, so `/sync/push` and
  `/sync/pull` will not carry them.

`api/src/app.module.spec.ts` asserts this against the real Nest metadata graph,
so a future re-import fails the build rather than silently re-exposing the
domain. Reactivation is gated by ADR-P017 Decision 9.

Where the product needs the user's physical limitations, it uses the
**self-declared wellness safety profile** (ADR-P031), which is explicitly not a
medical record and says so on screen.

## Web

Public v1 on the Web is **account and recovery portals only** — password reset,
email verification and account deletion — as a statically prerendered shell
(ADR-P032). Every database-backed feature renders an explicit *unavailable on
Web* state rather than appearing broken (ADR-P019). This is a deliberate
boundary, not an omission; release-queue item 8 is where it is accepted or
re-scoped.

## Security & privacy

- Health free-text in the **retained** medical domain is AES-256-GCM encrypted
  at rest on device and server. Wellness and fitness data (progress metrics,
  workouts, food logs) is plaintext at rest, protected by app-private storage,
  TLS and access controls (ADR-P016 D1).
- TLS in transit; passwords Argon2-hashed; recovery tokens hashed at rest,
  single-use, 30-minute TTL.
- **API rate limiting and brute-force protection** (ADR-P020) and **HTTP
  hardening with graceful shutdown** (ADR-P021).
- Monitoring (Sentry) is wired but **inert** (no DSN); scrubbers exclude PII and
  PHI by design (ADR-P010). Runbook: `docs/SENTRY_ENABLEMENT.md`.
- Legal drafts (`docs/legal/*`) and the Play Data Safety mapping remain **DRAFT
  pending legal sign-off**, and must be refreshed for Phase 21 rather than the
  Phase 20 product.

## Known issues / accepted exceptions

- **Dependency advisories.** Critical is 0 in both packages, so the CI gate is
  unaffected, but the 2026-09-21 refresh records **11 HIGH (api)** and **7 HIGH
  (mobile)**, all triaged as unreachable — Metro and Expo build tooling on
  mobile; the Prisma CLI chain, `multer` (no multipart route exists) and
  `js-yaml` behind the `API_DOCS_ENABLED` gate on the API. **`RISK-002`** tracks
  the one reachable finding: `qs`, on the Express request path, with a
  non-breaking fix awaiting owner authorization.
- **`BUG-017`** — the Web portals never render dark. Native light/dark is
  verified; Web is evidenced as broken. Blocks gate 6.
- **Data export UI** is not implemented; account deletion **is** available
  in-app.
- **The app ships largely default Material Design 3.** ADR-P022's Inter, icon
  delivery, motion and dark surface-tint elevation are unimplemented, and the
  icon delivery mechanism is still unselected.
- `PERF-001`'s dashboard-render and SQLite-init measurements need instrumentation
  the app does not have.
